# 공용 Checkbox UI wrapper 도입 수행계획서

GitHub Issue: [#15](https://github.com/jinzer0/Prompter/issues/15)
마일스톤: M012

## 목적

renderer 전반의 raw checkbox 반복을 공용 `Checkbox`/`CheckboxRow` wrapper로 정리해 크기, 정렬, focus, disabled 상태를 일관되게 유지한다. native checkbox semantics와 기존 설정/스캔/임포트 동작은 보존한다.

## 배경

여러 컴포넌트에서 `<input type="checkbox">`와 `accent-accent`, label/card 스타일이 반복되어 drift 위험이 있다. DESIGN.md는 local component wrapper와 visible focus를 요구하므로 checkbox도 UI primitive로 승격할 가치가 있다.

## 범위

### 포함

- `renderer/src/components/ui/` 하위 checkbox wrapper 추가
- app-lock, backup import, maintenance scan, privacy settings, project context profile, compiler suggested tags 중 계획서 승인 범위 사용처 교체
- 접근성 label, checked/disabled 상태 유지 검증

### 제외

- radio/switch/segmented control 도입
- 설정 의미나 저장 로직 변경
- 색상 팔레트 변경
- 모든 form layout 전면 리팩토링

## 설계 방향

- 기존 native checkbox를 감싸되 제어 상태와 접근성 이름 전달을 명확히 한다.
- 카드형 설명 checkbox와 inline checkbox를 구분하되 과도한 variant를 만들지 않는다.
- 기존 `Input`, `Button`, `Select` wrapper의 단순한 API 스타일을 따른다.

## 리스크

- **과도한 추상화**: checkbox/row 수준으로 제한하고 switch 류 추상화는 만들지 않는다.
- **접근성 회귀**: label wrapping과 aria-label을 기존보다 약화하지 않는다.

## 승인 요청 사항

- Issue #15을 `local/task15`에서 시작하고 위 범위와 단계 경계로 구현계획서 작성 및 후속 구현을 진행한다.
- 수행계획서 승인 전에는 구현계획서 작성, 제품 코드 변경, 검증 목적 외 변경을 진행하지 않는다.
- 범위 제외 항목은 별도 이슈 또는 별도 승인 없이는 다루지 않는다.

승인되면 `task_m012_15_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
