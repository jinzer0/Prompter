# Phase 20: 앱 잠금 / 로컬 세션 보호

당신은 Prompter라는 Electron 데스크톱 앱을 개발하고 있습니다.

Prompter는 로컬 우선(local-first) 프롬프트 컴파일러이자 프롬프트 라이브러리입니다. 이 앱의 목적은 모호한 인간의 요청을 에이전트가 실행 가능한 프롬프트로 변환하고, 이를 버전 관리되는 프롬프트 자산으로 저장하며, Codex, Claude Code, Cursor 및 일반 LLM 에이전트에 사용할 수 있도록 내보내는 것입니다.

현재 프로젝트 repository는 사용자가 제공한 Prompter 저장소를 기준으로 작업합니다.

이 작업은 **Phase 20: 앱 잠금 / 로컬 세션 보호**입니다.

## 목표

Prompter 안에는 프롬프트, 프로젝트 컨텍스트, 템플릿, 하네스, 품질 리뷰, 백업 데이터 등 민감할 수 있는 로컬 정보가 쌓입니다. Phase 19에서 민감정보 감지와 암호화 백업을 구현했으므로, 이제 사용자가 앱을 열어둔 상태에서 자리를 비우거나 화면을 공유할 때 기본적인 보호를 제공하는 **앱 잠금 기능**을 구현합니다.

이 기능은 다음을 제공합니다.

* 수동 앱 잠금
* 자동 잠금 타이머
* 앱 시작 시 잠금 옵션
* 잠금 화면
* 로컬 passphrase 기반 unlock
* passphrase hash 저장
* passphrase 원문 저장 금지
* 잠금 상태에서 민감한 UI 숨김
* 잠금 상태에서 DB 내용 노출 금지
* 잠금 상태에서 LLM 호출, export, backup, clipboard read 금지

중요한 제한:

* 이 Phase는 **전체 DB 암호화**를 구현하지 않습니다.
* 이 Phase는 **운영체제 수준 보안**을 대체하지 않습니다.
* 이 Phase는 앱 UI와 세션 접근을 보호하는 기능입니다.
* 로컬 DB 파일 자체 암호화는 별도 Phase로 미룹니다.

인간은 노트북을 열어두고 카페 화장실에 가는 놀라운 결정을 하므로, 최소한 앱 화면이라도 잠그는 겁니다.

## 앱 잠금의 보안 범위

이 기능은 다음을 보호합니다.

* 앱 UI 접근
* Prompt library 표시
* Prompt detail 표시
* PromptCompilerPanel draft 표시
* project context profile 표시
* templates 표시
* export / backup / clipboard 기능 접근
* LLM analyze / compile / review 실행
* Settings의 민감한 상태 확인

이 기능은 다음을 보호하지 않습니다.

* 이미 디스크에 저장된 SQLite DB 파일 자체
* OS 계정이 탈취된 상황
* 디스크 전체 접근 권한을 가진 공격자
* malware
* screen recording malware
* 파일 시스템에서 직접 DB를 읽는 공격자

UI에 이 차이를 명확히 설명하세요.

문구 예:

> 앱 잠금은 Prompter 화면과 세션 접근을 보호합니다. 로컬 데이터베이스 파일 자체를 암호화하는 기능은 아닙니다.

### 1. App Lock 설정

Settings에 “앱 잠금” 섹션을 추가합니다.

설정 항목:

* 앱 잠금 사용 여부
* 앱 시작 시 잠금
* 비활성 상태 자동 잠금
* 자동 잠금 시간
* 잠금 시 민감한 화면 숨김
* passphrase 변경
* 앱 잠금 비활성화

권장 setting keys:

* app_lock_enabled
* app_lock_on_start
* app_lock_timeout_minutes
* app_lock_hide_on_blur, 선택
* app_lock_require_for_export
* app_lock_require_for_backup
* app_lock_require_for_llm

기본값:

* app_lock_enabled: false
* app_lock_on_start: false
* app_lock_timeout_minutes: 15
* app_lock_hide_on_blur: false
* app_lock_require_for_export: true
* app_lock_require_for_backup: true
* app_lock_require_for_llm: true

주의:

* quick_capture_* settings를 추가하지 마세요.
* global shortcut 설정을 추가하지 마세요.
* OS 전역 잠금 기능을 구현하지 마세요.

### 2. Passphrase 설정

사용자가 앱 잠금을 활성화할 때 passphrase를 설정해야 합니다.

요구사항:

* passphrase 입력
* passphrase confirmation 입력
* 최소 길이 검증
* 너무 짧은 passphrase 경고
* passphrase 원문 저장 금지
* passphrase 로그 출력 금지
* passphrase renderer 장기 보관 금지
* 설정 성공 후 입력 필드 clear

권장 최소 정책:

* 최소 8자
* 공백만 있는 값 거부
* confirmation 불일치 시 오류

강한 정책을 강제하지는 마세요.
토이프로젝트 앱에 기업 보안 정책을 밀어 넣으면 사용자가 앱을 잠그기 전에 앱을 지웁니다.

### 3. Passphrase Hash 저장

passphrase 원문은 절대 저장하지 않습니다.

권장 방식:

* main process에서 Node.js crypto 사용
* scrypt 또는 pbkdf2 사용
* salt 랜덤 생성
* hash 저장
* salt 저장
* kdf metadata 저장

저장 위치:

* settings table에 lock metadata 저장 가능
* 또는 별도 local security settings store 사용 가능

권장 저장 구조:

```json
{
  "enabled": true,
  "kdf": "scrypt",
  "salt": "base64",
  "hash": "base64",
  "createdAt": 1234567890,
  "updatedAt": 1234567890
}
```

주의:

* passphrase 원문 저장 금지
* passphrase hash를 renderer에 반환하지 마세요
* salt/hash를 logs에 출력하지 마세요
* hash 비교는 main process에서만 수행합니다

### 4. Unlock Flow

앱이 locked 상태이면 잠금 화면을 표시합니다.

잠금 화면에는 다음을 표시합니다.

* Prompter 로고 또는 이름
* “앱이 잠겨 있습니다”
* passphrase 입력
* unlock 버튼
* 실패 메시지
* optional: “passphrase를 잊은 경우 복구할 수 없습니다” 안내

동작:

* 사용자가 passphrase 입력
* renderer는 unlock 요청을 preload bridge로 전달
* main process가 hash 검증
* 성공 시 session unlocked
* 실패 시 오류 반환
* 실패 횟수 표시, 선택

보안 요구사항:

* renderer에 hash 반환 금지
* unlock 실패 시 passphrase echo 금지
* 실패 로그에 passphrase 포함 금지
* unlock 성공 후 passphrase input clear
* unlock 상태는 메모리 세션 상태로만 유지
* 앱 재시작 시 app_lock_on_start가 true면 다시 locked

---

### 5. Session Lock State

main process 또는 renderer top-level state에서 현재 lock state를 관리합니다.

권장 방식:

* main process에 authoritative lock state 유지
* renderer는 window.prompter.appLock.getState()로 조회
* lock/unlock 변경 시 기존 menu action channel 또는 안전한 event pattern 사용
* 새 window.prompter.appEvents.*를 만들지 마세요

가능한 API:

* window.prompter.appLock.getState()
* window.prompter.appLock.setup(input)
* window.prompter.appLock.unlock(input)
* window.prompter.appLock.lock()
* window.prompter.appLock.disable(input)
* window.prompter.appLock.changePassphrase(input)
* window.prompter.appLock.getSettings()
* window.prompter.appLock.updateSettings(input)

LockState:

```ts
type AppLockState = {
  enabled: boolean
  locked: boolean
  lockOnStart: boolean
  timeoutMinutes: number
  lastUnlockedAt: number | null
}
```

주의:

* passphrase hash는 반환하지 않음
* passphrase 원문은 반환하지 않음
* renderer에서 crypto 검증하지 않음

### 6. Manual Lock

사용자가 명시적으로 앱을 잠글 수 있어야 합니다.

진입점:

* Settings > Lock now
* 앱 메뉴

  * Prompter 또는 File 메뉴에 “Lock Prompter”
* 키보드 accelerator, 앱 포커스 상태에서만

  * CmdOrCtrl+L 또는 CmdOrCtrl+Shift+L

메뉴 추가 시:

* 기존 menu.onAction / MENU_ACTION_CHANNEL 패턴 재사용
* window.prompter.appEvents.* 추가 금지
* window.prompter.shortcuts.* 추가 금지
* globalShortcut 사용 금지

동작:

* lock action 실행
* 모든 민감 UI가 lock screen으로 덮임
* current draft 내용이 화면에 보이지 않음
* unlock 전까지 주요 API 호출 차단

### 7. Auto Lock Timer

비활성 상태가 일정 시간 지나면 앱이 자동 잠금됩니다.

비활성 기준:

* renderer user activity 기준

  * keydown
  * pointerdown
  * mousemove, throttle 필요
  * focus
* 또는 main window blur 기준, 선택

권장 MVP:

* renderer에서 user activity timestamp 관리
* interval로 timeout 확인
* timeout 도달 시 window.prompter.appLock.lock() 호출
* app_lock_enabled가 false면 동작하지 않음
* timeoutMinutes는 settings에서 읽음

주의:

* background daemon 만들지 마세요
* OS globalShortcut 만들지 마세요
* 앱이 잠겨도 DB를 지우거나 draft를 삭제하지 마세요
* 자동 잠금은 자동 저장이 아닙니다
* 자동 잠금은 자동 LLM 호출과 무관합니다

### 8. Blur 시 숨김, 선택 구현

선택 기능으로 앱 window가 blur될 때 민감한 화면을 숨길 수 있습니다.

설정:

* app_lock_hide_on_blur: boolean

동작:

* window blur 시 전체 lock은 하지 않고 privacy overlay만 표시 가능
* window focus 시 overlay 해제
* 또는 lock 처리 가능하지만 MVP에서는 overlay 권장

주의:

* 구현 범위가 커지면 제외해도 됩니다.
* 이 기능은 OS screen capture 보호가 아닙니다.
* macOS 보안 레벨의 screen shield가 아닙니다.
* 단순 UI overlay입니다.

### 9. Locked State에서 API Guard

앱이 locked 상태이면 민감한 작업을 막아야 합니다.

잠금 상태에서 차단할 API:

* promptCompiler.analyze
* promptCompiler.compile
* promptQuality LLM review
* promptQuality local review, 선택
* exports.formatPrompt
* exports.savePromptToFile
* backup export/import
* encrypted backup export/import
* clipboard.readText
* clipboard.copyText, 선택
* privacy scan, 선택
* prompts CRUD
* project context CRUD
* prompt templates CRUD
* harness templates CRUD

MVP 정책:

* locked 상태에서는 renderer UI가 lock screen만 보여야 하므로 대부분 API 호출이 발생하지 않아야 합니다.
* 그래도 main IPC handler에서 locked guard를 추가해 민감 API를 방어하세요.
* lock/unlock/settings 관련 API는 예외입니다.

권장 구조:

* main process에 requireUnlocked() helper 추가
* sensitive IPC handler 시작 부분에서 호출
* locked면 structured error 반환

예:

```ts
if (appLockService.isLocked()) {
  throw new AppError("APP_LOCKED", "Prompter is locked.")
}
```

주의:

* unlock API는 locked 상태에서도 허용
* getLockState는 허용
* setup은 lock이 비활성인 상태에서 허용
* disable/changePassphrase는 unlock 상태에서만 허용

### 10. UI Overlay / Lock Screen

앱 전체를 잠금 화면으로 덮습니다.

요구사항:

* AppShell 최상단에서 lock state를 확인
* locked면 기존 UI 대신 LockScreen 표시
* 기존 prompt list, draft, context, templates, insights가 화면에 보이지 않음
* unlock 성공 후 기존 UI 복귀
* unlock 실패 시 오류 표시

주의:

* lock screen 아래에 민감 데이터가 DOM에 남아 있더라도 시각적으로 가려질 수 있습니다.
* 더 엄격히 하려면 locked 상태에서는 민감 컴포넌트를 render하지 않는 구조를 권장합니다.
* MVP에서는 AppShell 레벨 conditional render를 사용하세요.

### 11. Current Draft 보호

잠금 시 current draft를 자동 삭제하지 마세요.

정책:

* draft는 메모리 state에 유지 가능
* locked 화면에서는 보이지 않아야 함
* unlock 후 draft 복원
* 자동 persistence 없음
* quick capture 원문도 locked 화면에서는 숨김
* lock 때문에 자동 save하지 않음

중요:

* lock action은 originalInput을 trim/cleanup하지 않음
* lock action은 draft를 DB에 저장하지 않음
* lock action은 stale state를 변경하지 않음
* unlock action은 analyze/compile/review를 자동 실행하지 않음

---

### 12. Settings 보호

앱 잠금 설정 자체도 안전해야 합니다.

정책:

* 잠금 비활성화는 passphrase 확인 필요
* passphrase 변경은 현재 passphrase 확인 필요
* timeout 변경은 unlock 상태에서만 가능
* app_lock_enabled가 true이면 Settings의 민감 섹션 접근은 unlock 상태에서만 가능

Disable flow:

* 현재 passphrase 입력
* 검증 성공
* lock metadata 삭제 또는 enabled false
* lock state unlocked
* 설정 저장

Change passphrase flow:

* 현재 passphrase 입력
* 새 passphrase 입력
* confirmation
* 새 hash/salt 생성
* 기존 hash 대체

---

### 13. Lost Passphrase UX

passphrase를 잊은 경우 복구할 수 없음을 안내합니다.

MVP 정책:

* passphrase reset 기능은 구현하지 마세요.
* “passphrase를 잊은 경우 앱 잠금을 해제할 수 없습니다. 로컬 DB 파일을 직접 삭제하거나 앱 데이터를 초기화해야 할 수 있습니다.” 안내 정도만 표시
* 데이터 초기화 기능은 이번 Phase에서 구현하지 않습니다.

* verifyPassphrase fails with wrong passphrase

* unlock sets locked false
* unlock fails with wrong passphrase

* locked rejects export save
* locked rejects backup export
* locked rejects clipboard.readText
* locked allows appLock.unlock
* locked allows appLock.getState

* AppShell content hidden when locked
* unlock error displayed
* unlock success restores app
* auto lock after timeout
