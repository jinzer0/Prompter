# M012 디자인 리팩토링 통합 검증 수행계획서

GitHub Issue: [#26](https://github.com/jinzer0/Prompter/issues/26)
마일스톤: M012

## 목적

M012 디자인 리팩토링 task `#14-#19`가 모두 `master`에 병합된 상태에서 통합 검증을 수행한다. Electron window option, renderer UI primitive, checkbox, dialog, selectable card, metric card 변경이 함께 적용된 최종 `master`가 타입, lint, 테스트, smoke 기준을 만족하는지 확인한다.

검증 중 제품 코드 문제를 발견하면 임의 수정하지 않고 실패 근거와 후속 조치 기준을 보고한다.

## 배경

`#14-#19`는 병렬 worktree/PR로 진행됐고 PR merge 과정에서 `mydocs/orders/20260922.md`, backup import, backup panel parts 충돌을 해결했다. 개별 PR 검증은 완료됐지만 병합 후 전체 조합 상태를 별도 task로 확인해야 한다.

현재 추가로 열린 Dependabot PR은 없으며, 남은 dependency alert는 별도 remediation task 대상이다. 이 task는 dependency remediation이 아니라 M012 디자인 리팩토링 통합 검증에 한정한다.

## 범위

### 포함

- 최신 `origin/master` 기준 task branch 검증
- `npm run typecheck`
- `npm run lint`
- relevant focused tests 또는 가능하면 `npm test`
- 가능한 경우 `npm run test:smoke`
- `git diff --check`, `git status --short`
- 통합 검증 단계 보고서와 최종 보고서 작성

### 제외

- 새 UI 리팩토링 추가 구현
- dependency remediation 직접 수행
- Dependabot alert 수정
- release/package/notarization 작업
- 디자인 토큰/색상 변경
- 검증 실패 원인 수정 코드 작성

## 설계 방향

- 검증은 최신 `origin/master`를 기준으로 하며 task 문서 외 제품 코드는 변경하지 않는다.
- 실패 시 명령, 핵심 오류, 재현 조건, 관련 파일/영역, 후속 이슈 필요 여부를 보고한다.
- native module rebuild가 필요한 검증은 기존 npm scripts를 사용한다.
- smoke는 build 산출물이 필요한 경우 `npm run build`를 먼저 수행한다.

## 잠정 단계

- **Stage 1 — 검증 기준선 확인**
  - `origin/master` 동기화, branch 상태, dependency/runtime 준비 상태를 확인한다.
  - `git status --short`, `git diff --check`, issue/PR 병합 상태를 확인한다.
- **Stage 2 — 정적/단위 검증**
  - `npm run typecheck`, `npm run lint`, relevant focused tests 또는 가능한 범위의 `npm test`를 실행한다.
  - 실패 시 원인과 후속 조치 기준을 기록한다.
- **Stage 3 — Electron smoke와 최종 보고**
  - build가 필요하면 `npm run build` 후 `npm run test:smoke`를 실행한다.
  - 통합 검증 결과보고서와 PR 준비 산출물을 작성한다.

## 검증 계획

### 단계별 검증

- Stage 1
  - `git status --short --branch`
  - `git diff --check`
  - `gh issue view 14-19/26` 또는 PR/issue 상태 확인
- Stage 2
  - `npm run typecheck`
  - `npm run lint`
  - `npm test` 또는 실패/시간 제약 시 관련 focused test 명령
- Stage 3
  - `npm run build`
  - `npm run test:smoke`
  - `git status --short`
  - `git diff --check`

### 통합 검증

- 최신 `master`에서 `#14-#19` 변경이 함께 적용된 상태를 검증한다.
- 검증 실패가 있으면 실패 원인과 후속 이슈 필요 여부를 판단한다.
- `git status --short`가 PR 준비 전 문서 변경 외 예기치 않은 출력을 보이지 않는다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **native module rebuild 시간/환경 의존성**: 기존 npm scripts만 사용하고 실패하면 환경/명령/오류를 보고한다.
- **smoke 선행 build 누락**: Electron smoke 전 `npm run build`를 수행한다.
- **검증 중 제품 코드 문제 발견**: 이 task에서는 임의 수정하지 않고 후속 이슈로 분리한다.

## 승인 요청 사항

- Issue #26을 `local/task26`에서 시작하고 위 범위와 단계 경계로 구현계획서 작성 및 통합 검증을 진행한다.
- 제품 코드 변경 없이 검증과 보고 산출물만 작성한다.
- 실패 수정은 별도 이슈/승인 없이는 진행하지 않는다.

승인되면 `task_m012_26_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
