# Prompter — Experience Contract

## Foundation

macOS Electron에서 코딩·에이전트용 프롬프트를 찾아 복사하고, 편집·버전 관리·컴파일하는 도구다. 규제 산업 대상이나 규정 준수 약속은 확인되지 않았다. 여정의 주인공은 **작업지시자(이 대화에서 사용 흐름을 설명한 사용자)**이며 가상의 인물·팀·업무 환경을 만들지 않는다.

사용자는 A안(탐색/목록/오른쪽 본문+컴파일러), 현재 편집 내용 복사, 기본 새 버전 저장과 별도 복제, 명시적 컴파일 결과 적용, 창 1180×760·최소 1024×720을 승인했다. 이 계약은 승인된 UX 방향의 구현 기준이며 기능 구현·출시 완료를 뜻하지 않는다. 시각 기준은 [DESIGN](../../DESIGN.md), 범위 근거는 [승인 계획](../../mydocs/plans/task_m012_31.md)이다.

구성요소의 시각 토큰은 DESIGN에서 정의하며 이 문서는 새 토큰을 만들지 않는다. 계약의 시안 우선순위는 DESIGN의 규칙을 따른다.

본문은 `{typography.body.fontSize}`, 편집 도구 사이 간격은 `{spacing.2}`를 참조한다. 설명은 `{colors.secondary-light}` / `{colors.secondary-dark}`를 사용한다. 실제 값과 시각 상태의 소유권은 DESIGN에 있다.

기존 스키마·저장 경로·IPC 보안 경계를 보존한다. `app_theme=system|light|dark`와 테마 선택 UI는 이미 있으며, 관찰된 문제는 light가 저장돼도 dark로 그려지는 연결 실패다. OS `nativeTheme`는 main 소유, renderer는 검증된 typed bridge만 사용한다. 설정을 중복 신설하지 않는다.

## Information Architecture

아래 경로는 도달 가능한 UI 계약이며 새로운 URL 라우터나 구현 완료를 뜻하지 않는다. 단순 시안에서 생략된 기능도 명시적 버튼·탐색 항목으로 연결한다.

| 표면 | 진입·복귀 경로 | 유지할 역할 |
|---|---|---|
| Library 탐색·목록 | 앱 시작 / 사이드바의 Library; 프로젝트 선택 → 검색·태그 필터 → Prompt Row | 선택한 프로젝트의 프롬프트만 다룬다. 시안의 ‘모든 프롬프트’는 프로젝트 내 전체이며 전 프로젝트 검색 기능이 아니다. 프로젝트 생성·관리는 프로젝트 영역의 관리 동작으로 연다. |
| 선택 상세·편집 | Prompt Row → 오른쪽 상단 Prompt Editor | 본문·복사·새 버전 저장·복제하여 저장을 우선한다. 목록 머리의 ‘새 프롬프트’도 기존 생성 기능으로 연결한다. |
| 버전·태그·내보내기·품질 | Prompt Editor의 ‘버전 이력’, ‘태그 편집’, ‘내보내기’, ‘품질 검토’ | 저장 버전 조회·태그 편집·기존 내보내기·저장된 검토 열람 및 명시적 검토 실행을 보존한다. 더보기로 묶어도 메뉴명과 실제 도착점이 있어야 한다. |
| Compiler | 오른쪽 하단 → 핵심 요청·프로젝트 바인딩 → ‘추가 옵션’ → 별도 결과 | 기존 시나리오·대상 에이전트·기본값·필수 출력 섹션을 유지한다. 요청 입력과 편집 본문은 별개다. |
| 프로젝트 컨텍스트 | 프로젝트 영역 ‘컨텍스트 관리’; Compiler 추가 옵션 ‘컨텍스트 선택/관리’ | 기존 프로필·값의 조회·편집·명시적 저장을 보존하며 선택 프로젝트와 바인딩을 표시한다. |
| 템플릿·하네스 | Compiler 추가 옵션 ‘템플릿 선택/관리’, ‘하네스 선택/관리’ | 기존 생성·편집·선택과 템플릿 계보를 보존한다. 관리자 진입이 템플릿 적용·컴파일을 자동 실행하지 않는다. |
| Settings | 사이드바 하단 ‘설정…’ → ‘라이브러리로 돌아가기’ | 화면 및 기본값 / 키 관리 / 앱 잠금 / 백업 / 수동 정리 / 개인정보 설정을 분리한다. 진입만으로 편집 초안을 버리거나 저장 확인을 새로 요구하지 않는다. |
| Insights | 사이드바 ‘Insights’ → Library 또는 관련 설정 | 사이드바를 남기고 나머지 작업 공간을 대체한다. 읽기 전용이며 기존 정보 순서를 유지한다. 사용자가 철회한 재배치 요구를 적용하지 않는다. |
| Privacy Center | 사이드바 ‘Privacy Center’ → finding의 관련 관리자/상세 또는 Library | 같은 작업 공간 예외다. 기본 열람은 읽기 전용이고 검사는 명시적 수동 동작이다. 마스킹된 결과와 기존 확인 흐름을 보존한다. |

[Library 시안](mockups/key-library.html)은 세 열과 본문 우선 순서를, [Settings 시안](mockups/key-settings.html)은 별도 설정·복귀를 보여 준다. 시안은 전체 기능 목록이나 작동 증거가 아니다.

**시안 범위:** 사용자는 Library·Settings·미저장 보호의 세 시안으로 충분하다고 확인했다. 컴파일 결과와 적용·교체 확인, 버전·태그·컨텍스트·템플릿·하네스·품질·내보내기, 설정 세부 작업, Insights·Privacy는 아래 행동·상태 표를 구현 기준으로 삼는다. 시안에 안 보인다는 이유로 진입점이나 기능을 제거하지 않는다.

## Voice and Tone

| 사용 문구·원칙 | 피할 표현·이유 |
|---|---|
| ‘복사’, ‘새 버전 저장’, ‘복제하여 저장’, ‘편집에 적용’으로 결과를 구별한다. | 모호한 ‘실행’으로 복사·컴파일·저장을 섞지 않는다. |
| ‘저장하지 못했습니다. 편집 내용은 그대로 남아 있습니다.’처럼 상태와 다음 행동을 설명한다. | 내부 hook·IPC·binding 오류명을 사용자 지시문으로 노출하지 않는다. |
| ‘버전은 저장됐습니다. 검색 목록 갱신에 실패했습니다.’로 부분 성공을 정확히 알린다. | 부수 작업 실패를 본문 미저장으로 표시하거나 무조건 ‘다시 저장’을 권하지 않는다. |
| ‘프로젝트를 다시 연결하면 생성과 적용을 계속할 수 있습니다.’처럼 비활성 원인을 설명한다. | 비활성 버튼만 남기거나 색·아이콘만으로 경고하지 않는다. |

## Component Patterns

이름은 DESIGN의 Components와 일치한다. 새 라이브러리 도입이 아니라 기존 래퍼와 합성 영역의 행동 계약이다.

| 이름 | 행동 규칙 |
|---|---|
| Button | native 키보드 동작을 유지한다. 복사·저장·복제는 별개이며 쓰기 진행 중 중복 제출을 막고 실패 후 명시적 재시도를 제공한다. |
| Input | 보이는 라벨 또는 접근 가능한 이름을 제공한다. 검색 입력은 편집 초안을 변경하지 않으며 오류 후 입력을 보존한다. |
| Textarea | 편집 본문·컴파일 요청·결과 preview를 서로 다른 상태로 보관한다. bound preview의 기존 편집 가능성은 보존하되 편집기 반영은 명시적 적용으로만 한다. unbound preview는 선택·복사 가능한 읽기 전용이다. |
| Badge | 버전·연결·저장 상태를 텍스트로 읽게 한다. 상태 변경 알림은 관련 작업 결과만 전달하고 매 렌더마다 반복하지 않는다. |
| Select | 기존 native 단일 선택과 라벨을 보존한다. 테마는 system/light/dark 기존 값, 컴파일 선택지는 기존 계약의 값만 사용한다. |
| Card | 관련 필드를 제목으로 묶는다. 컨테이너 전체를 보이지 않는 클릭 영역으로 만들거나 진입만으로 작업을 실행하지 않는다. |
| Tabs | tablist/tab/tabpanel 관계와 선택 상태를 제공한다. 키보드 이동·패널 전환 후 초안과 초점을 유지한다. |
| Empty State | 최초 비어 있음·검색 결과 없음·미선택을 구별하고 생성·필터 해제·선택 등 해당 맥락의 행동을 제공한다. |
| SidebarItem | 현재 탐색 위치를 노출한다. 프로젝트/프롬프트 변경으로 편집 대상이 바뀌면 미저장 보호를 적용하며 설정 진입만으로는 적용하지 않는다. |
| Panel | 이름 있는 영역과 읽기 순서를 제공한다. Settings·Insights·Privacy Center에서 Library로 돌아오면 선택·검색/필터·본문·컴파일 초안과 가능한 스크롤/초점 위치를 복원한다. |
| Alert Dialog | labelled/described alertdialog와 aria-modal을 유지한다. 초기 초점은 안전한 취소, Escape는 취소, 배경은 비활성이다. 취소 후 원래 편집 위치 또는 안정된 호출 컨트롤로 초점을 돌린다. |
| Privacy Finding List | idle/scanning/ready/error를 구별하고 비활성 검사 사유를 노출한다. finding 이동은 관련 관리자/상세에 초점만 주며 검사·수정·삭제·리뷰를 실행하지 않는다. |
| Window Chrome | 실제 native traffic lights와 OS 닫기 경로를 유지한다. 닫기는 dirty 보호를 거치며 일반 컨트롤을 drag 영역에 포함하지 않는다. 브라우저 확대/축소 단축키를 가로채지 않는다. |
| Prompt Row | 선택 후 해당 프롬프트의 본문과 버전을 로드한다. dirty 상태에서는 전환을 보류하고 결정 전까지 기존 선택 표시·본문을 유지한다. |
| Prompt Editor | ‘복사’는 현재 편집 텍스트, Cmd+S/‘새 버전 저장’은 기존 프롬프트의 새 버전이다. ‘복제하여 저장’만 별도 프롬프트를 만든다. 저장 없이 복사할 수 있다. |
| Compiler | 생성은 별도 preview를 만든다. ‘편집에 적용’ 후에도 미저장이며 dirty 본문 교체는 확인이 필요하다. unbound 상태에서는 기존 재연결 안내·복사는 유지하고 생성·템플릿 적용·저장/본문 적용을 막는다. |
| Settings Row | 기존 설정의 저장 동작·검증·실패 표시를 보존한다. 키는 상태/마스킹만 표시하고 테마 변경이나 설정 진입이 다른 작업을 자동 실행하지 않는다. |

## State Patterns

| 표면·상태 | 반응·복구 |
|---|---|
| Library cold-load / 목록·본문 로딩 | 로딩을 비어 있음과 구분한다. 늦게 도착한 이전 선택의 응답이 최신 선택을 덮지 않게 하고 읽기 실패 시 재시도와 기존 초안을 유지한다. |
| 프로젝트 없음 / 빈 프로젝트 / 검색 0건 / 미선택 | 각각 프로젝트 생성, 새 프롬프트, 필터 해제, 행 선택을 안내한다. 미선택에서는 대상 없는 저장·복제를 막는다. |
| 검색·태그 로딩 실패 | 목록 상태 오류를 설명하고 재조회한다. 편집 텍스트나 이미 저장된 버전을 되돌리지 않는다. |
| Prompt Editor clean / dirty / saving / saved / error | 저장한 스냅샷 기준으로 dirty를 계산한다. 저장 성공 후 추가 편집이 있다면 여전히 dirty다. 실패하면 현재 본문·선택·컴파일 요청을 남긴다. |
| 버전 저장 성공 + 검색 갱신·태그 등 부수 작업 실패 | 저장된 버전 식별자와 clean 기준을 유지하고 실패 영역만 안내·재시도한다. 같은 본문 버전을 중복 쓰거나 거짓 ‘미저장’을 표시하지 않는다. 실제 미저장 태그는 본문과 별도로 표시한다. |
| 버전·태그·품질·내보내기 | 없음/로딩/오류를 구분하고 기존 이력·리뷰를 보존한다. 로컬 품질 검토는 명시적 실행, LLM 검토의 unavailable/missing-key 상태는 그대로 설명한다. OS 저장 대화상자 취소는 오류가 아니며 파일 권한 실패는 위치 재선택을 안내한다. |
| 컨텍스트·템플릿·하네스 관리자 | 빈 목록·선택 없음·로딩·저장 실패에서 생성/선택/재시도와 초안 보존을 제공한다. 다른 프로젝트에 잘못 적용하지 않고 dirty 본문을 자동 교체하지 않는다. |
| Compiler idle / generating / ready / error / offline / missing-key | 생성 중 중복 요청을 막고 실패 시 입력과 이전 결과를 보존한다. 네트워크·키 오류는 해당 기능에 한정하며 로컬 탐색·편집·저장·복사를 막지 않는다. |
| Compiler unbound / 재연결 실패 | 결과는 읽기·선택·복사 가능하다. 대상 프로젝트와 재연결 동작을 설명하고 성공 전 적용·생성·저장은 비활성이다. |
| Settings 로딩 / 테마 저장 중·실패 / 복귀 | 기존 저장값과 선택 중 값을 구분한다. 실패를 성공처럼 표시하지 않고 재시도를 제공한다. 복귀 시 Library 초안을 유지한다. |
| 키 관리 / 앱 잠금 | 키 없음·마스킹 상태·보안 저장 불가·잠금·인증 실패를 기존 경계대로 처리한다. raw key 조회를 renderer에 추가하지 않고 잠금·세션 폐기를 우회하지 않는다. |
| 백업·가져오기 / 수동 정리 | 대화상자 취소·권한 거부·검증/충돌 오류를 구별한다. 가져오기 검증 preview·충돌 선택, 정리 scan→preview→확인·세션 검증을 유지한다. 자동 스캔·예약·지속 보고서를 약속하지 않는다. |
| Insights 로딩 / 비어 있음 / 오류 | 읽기 전용 조회·재조회만 한다. 진입/복귀가 유지보수·LLM·저장·파일/저장소 스캔을 시작하지 않는다. 정보 순서는 변경하지 않는다. |
| Privacy Center idle / disabled / scanning / ready / error | 수동 검사 전에는 검사 안 함을 표시한다. 설정상 비활성 이유, 진행 알림, masked 그룹·수·경고·오탐 가능성, 명시적 재시도를 보존한다. 열람/복귀로 검사·자동 가림·변경을 시작하지 않는다. |
| 모든 표면 focus / disabled / 오류 | focus를 선택과 구분하고 비활성 원인·오류 해결 행동을 읽을 수 있게 한다. 탐색·경고 이후 안정된 제어로 초점을 복원한다. |

## Interaction Primitives

- 클릭과 native 키보드 조작이 같은 결과를 낸다. Cmd+S는 Library 편집 대상의 새 버전 저장이며 복제나 컴파일을 실행하지 않는다. 대상 없거나 변경 없으면 불필요한 버전을 만들지 않는다.
- 다른 프롬프트·프로젝트·이력 선택처럼 본문을 교체하는 이동과 OS 창 닫기는 dirty 확인을 거친다. ‘저장’ 성공 후 요청한 이동/닫기를 한 번만 수행하고, ‘버리기’는 현재 변경만 버리며 저장 이력을 지우지 않는다. ‘취소’는 이동을 철회한다.
- 저장 요청 중 반복 닫기·선택으로 확인창이나 쓰기를 중첩하지 않는다. 저장 중 새 편집이 생겼다면 그 변경까지 버리고 이동하지 말고 다시 안전한 결정을 받는다.
- 복사·컴파일은 프롬프트를 실행하지 않는다. 컴파일의 기존 외부 생성 요청과 키 보호 경계는 유지하되 생성 결과를 저장/적용한 것으로 오인시키지 않는다.
- 설정·Insights·Privacy Center 진입은 편집 초안을 보존하므로 진입만을 이유로 새 저장 확인을 넣지 않는다. 그 안에서 창을 닫으면 보존된 dirty 초안에도 닫기 보호가 적용된다.

## Accessibility Floor

- 작은 일반 텍스트는 4.5:1 목표로 DESIGN의 primary/secondary 조합을 사용한다. 현재 목업은 전체 접근성 검증 증거가 아니며 인증이나 전 조합 통과를 주장하지 않는다.
- Tab 순서는 탐색→검색/목록→본문 동작/편집→컴파일 순서다. native 텍스트 선택·키 입력을 보존하고 모든 아이콘 동작에 이름을 제공한다. 가려진 작업 공간은 접근성 트리와 탭 순서에서 제외한다.
- 목록 선택·현재 탐색·저장/생성 진행·오류를 역할과 상태로 전달한다. 중요한 결과는 적절한 상태 알림으로 전달하되 입력 중 매 글자를 읽지 않는다. 대화상자의 초점은 내부에 머물고 Escape/취소로 안전하게 복원한다.
- reduced motion에서는 비필수 전환을 생략한다. OS/브라우저 확대·축소를 유지하고 읽기 크기를 줄여 공간 문제를 숨기지 않는다. 키보드만으로 내부 스크롤과 주요 행동에 도달할 수 있어야 한다.

## Responsive & Platform

| 조건 | 계약 |
|---|---|
| 기본 1180×760 / 최소 1024×720 | Library 세 열 모두 표시, shell 가로 스크롤 없음, 주요 복사·저장 행동이 잘리지 않아야 한다. 컨트롤 줄바꿈과 패널/본문 내부 세로 스크롤은 허용한다. |
| 최소 크기에서 긴 본문·옵션 | 오른쪽 내부 스크롤로 본문과 컴파일러 모두 접근 가능하게 한다. 프레임 overflow 숨김으로 필수 행동을 잘라내지 않는다. 목업 열 너비·높이는 조정 가능한 시작점이다. |
| 더 큰 창 / 긴 문자열·확대 | 남은 폭을 오른쪽에 배분하고 제목·설정 행을 줄바꿈한다. 최소 창보다 작은 별도 모바일/접힘 탐색은 이번 승인 범위가 아니다. 확대 시에도 조작에 도달해야 한다. |
| native 창 / 보안 | 시스템 traffic lights·닫기·창 이동·기존 보안 설정을 유지한다. 목업의 회색 원을 맞춤 창 버튼으로 구현하지 않는다. |

정적 시안은 실제 Electron 창 동작의 증거가 아니다. 실제 프레임·최소 크기·드래그 영역·초점·확대/축소는 제품 구현 단계에서 별도로 확인한다. 확인되지 않은 창 이동 원인을 확정하거나 수정됐다고 보고하지 않는다. 관찰 근거와 남은 검증은 [Stage 1 기록](../../mydocs/working/task_m012_31_stage1.md)에 둔다.

## Inspiration & Anti-patterns

- [Scratch](https://github.com/erictli/scratch)의 네이티브 창·제목 막대·도구 막대 통합감을 취한다. 저장 의미·색상·가짜 traffic lights를 복사하지 않는다.
- 창 안에 떠 있는 웹 카드, 큰 외곽 여백·그림자, 탐색을 밀어내는 거대한 관리 폼을 배제한다. 관리 기능은 실제로 도달 가능한 경로로 분리한다.
- 선택한 본문보다 컴파일러가 먼저 보이는 순서, 자동 저장/자동 적용, 내부 개발 용어, 프로젝트 범위를 흐리는 ‘모든 프롬프트’를 배제한다. Insights 정보 재배치는 철회된 요구다.

## Key Flows

### 1. 찾기·복사 — 작업지시자(이 대화에서 사용 흐름을 설명한 사용자)

1. 프로젝트를 선택하고 목록 검색·태그 필터로 필요한 프롬프트를 찾는다.
2. 행을 선택하여 오른쪽 상단 본문을 읽고, 필요하면 현재 편집 내용을 수정한다.
3. ‘복사’를 누른다. **절정:** 저장 여부와 무관하게 현재 편집 텍스트가 복사되고 완료 안내가 보인다.

**실패:** 결과 없음은 필터 해제를 안내한다. 로딩/클립보드 실패는 재시도를 제공하고 선택·본문을 유지한다. 다른 dirty 본문이 있으면 흐름 6을 먼저 거친다.

### 2. 수정·새 버전 저장 — 작업지시자(이 대화에서 사용 흐름을 설명한 사용자)

1. 저장된 버전을 열어 본문을 수정하고 ‘저장하지 않은 변경 있음’을 확인한다.
2. Cmd+S 또는 ‘새 버전 저장’을 누른다. 진행 중 중복 제출은 막는다.
3. **절정:** 같은 프롬프트에 새 버전이 생기고 실제 저장된 버전·상태가 표시된다.

**실패:** 쓰기 실패는 dirty 본문을 보존한다. 버전 저장 후 검색/태그 등 부수 작업이 실패하면 해당 작업만 재시도하며 버전을 다시 만들지 않는다. 저장 중 후속 편집은 별도 dirty로 남긴다.

### 3. 복제하여 저장 — 작업지시자(이 대화에서 사용 흐름을 설명한 사용자)

1. 원본을 열고 독립적으로 남길 현재 편집 내용을 준비한다.
2. 일반 저장 대신 ‘복제하여 저장’을 선택하여 기존 생성 절차의 필수 정보를 확인한다.
3. **절정:** 독립된 프롬프트가 생성되고 원본의 버전 이력은 바뀌지 않는다.

**저장 후:** 새 복제본을 선택하고 이어서 편집한다. 저장한 편집 스냅샷은 복제본의 clean 기준이며 원본은 변경하지 않는다. 이 명시적 복제 동작으로 같은 스냅샷이 보존되었으므로 원본을 다시 저장하라는 확인을 중복 표시하지 않는다.

**실패:** 생성 실패 시 원본 선택·편집 텍스트를 보존하고 성공 확인 전 새 항목을 가장하지 않는다. 저장 중 후속 편집은 복제 저장에 포함됐다고 표시하지 않으며, 초안을 잃는 선택 전환을 막고 안전한 결정을 받는다.

### 4. 컴파일·편집에 적용 — 작업지시자(이 대화에서 사용 흐름을 설명한 사용자)

1. 본문 아래 Compiler에서 바인딩된 프로젝트·요청을 확인하고 필요할 때 추가 옵션을 펼친다.
2. 생성하여 별도 결과 preview를 읽는다. 이 단계에서 본문·저장 버전은 바뀌지 않는다.
3. ‘편집에 적용’을 누른다. 본문이 dirty라면 교체 영향과 취소를 먼저 확인한다.
4. **절정:** 명시적 확인 뒤 결과가 편집 본문에 들어가고 미저장 상태가 된다. 저장하려면 흐름 2를 별도로 수행한다.

**실패:** 네트워크/키/생성 실패는 입력·이전 결과를 보존한다. unbound는 재연결을 안내하며 적용을 막는다. 교체 확인 취소는 본문과 preview를 모두 유지한다.

### 5. 테마 변경 — 작업지시자(이 대화에서 사용 흐름을 설명한 사용자)

1. Settings → 화면 및 기본값에서 기존 테마 Select를 연다.
2. 시스템 따르기/밝게/어둡게를 선택하고 기존 기본값 저장 동작으로 확정한다.
3. **절정:** 저장한 선택이 실제 전체 화면에 반영되고 다시 열어도 유지된다. system이면 OS 변경을 main의 nativeTheme에서 받아 따른다.

**실패:** 저장 실패는 선택 중 값과 저장값을 구분하고 재시도한다. 저장됐으나 시각 반영이 실패하면 저장을 반복시키지 않고 적용 오류를 알린다.

**저장 경계:** 기존 저장 동작을 유지하므로 선택만으로 별도 미리보기를 추가하지 않는다.

### 6. 미저장 선택 전환·창 닫기 — 작업지시자(이 대화에서 사용 흐름을 설명한 사용자)

1. 본문 수정 후 다른 프롬프트 선택 또는 OS 창 닫기를 요청한다.
2. [미저장 시안](mockups/key-unsaved.html)처럼 현재 화면을 유지하고 저장/버리기/취소를 보여 준다. 초기 초점은 취소다.
3. 저장은 새 버전 성공 후 요청을 진행하고, 버리기는 현재 변경만 버린 뒤 진행하며, 취소/Escape는 원래 편집 위치로 돌아간다.
4. **절정:** 선택한 보존/폐기 의도대로 한 번만 이동하거나 안전하게 편집을 계속한다.

**실패:** 본문 저장 실패는 이동/닫기를 막고 같은 대화상자에 오류·재시도·취소를 남긴다. 버전 저장 후 발생한 부수 작업 오류는 거짓 미저장 경고나 중복 쓰기를 만들지 않는다. 후속 dirty 편집이 없다면 성공한 본문 저장 기준으로 보류 요청을 진행한다.

### 7. 설정 진입·작업 복귀 — 작업지시자(이 대화에서 사용 흐름을 설명한 사용자)

1. 작성 중 사이드바 ‘설정…’을 연다. 본문·프로젝트·검색·컴파일 초안은 보존하며 진입만의 저장 확인은 없다.
2. 필요한 설정을 읽거나 명시적으로 변경한다. 진입만으로 키 노출·백업·검사·정리·LLM 호출을 시작하지 않는다.
3. ‘라이브러리로 돌아가기’를 누른다. **절정:** 이전 선택·편집·컴파일 맥락에서 바로 작업을 이어 간다.

**실패:** 설정 읽기/저장 실패는 해당 화면에서 재시도하며 Library 초안에 영향을 주지 않는다. 잠금이 발생하면 기존 인증·세션 경계를 먼저 따른다. 그 상태에서 닫을 때도 흐름 6의 보호를 우회하지 않는다.
