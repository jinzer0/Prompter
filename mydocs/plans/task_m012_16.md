# 반복 텍스트와 muted surface 스타일 primitive 정리 수행계획서

GitHub Issue: [#16](https://github.com/jinzer0/Prompter/issues/16)
마일스톤: M012

## 목적

반복되는 muted text, mono metadata, compact muted surface 패턴을 작은 공용 primitive로 정리해 DESIGN.md 기반 스타일 변경 비용과 UI drift를 줄인다.

## 배경

renderer 컴포넌트 전반에 `text-[12px] text-muted-strong`, `font-mono text-[11px] text-muted`, `rounded-card border border-border bg-panel-muted p-3` 같은 클래스 조합이 반복된다. 반복은 디자인 규칙과 맞지만 산재 상태라 유지보수 비용이 크다.

## 범위

### 포함

- HelperText/MetaLabel/StatusText/MutedWell 등 실제 반복에 근거한 최소 primitive 설계
- backup, privacy, app-lock, harness/template 주변 반복도가 높은 대상 일부 교체
- 적용 기준을 코드 구조나 보고서에 명확히 기록

### 제외

- 전체 renderer 파일 대규모 일괄 변환
- 색상/타이포그래피 스케일 변경
- DESIGN.md 팔레트 확장
- 기능 동작 변경

## 설계 방향

- 반복 빈도가 높은 class 조합만 primitive로 승격한다.
- 텍스트 semantic element는 호출부에서 필요한 HTML 의미를 보존할 수 있게 설계한다.
- surface primitive는 `Card`와 경쟁하지 않는 작은 muted well 용도로 제한한다.

## 잠정 단계

- **Stage 1 — 반복 패턴 확정과 primitive 설계**
  - 반복도 높은 텍스트/surface 패턴 선정
  - 불필요한 추상화 제외 확인
- **Stage 2 — 제한적 적용**
  - 선정 영역에 primitive 적용
  - 시각 클래스 동등성 확인
- **Stage 3 — 검증과 보고**
  - 타입/lint/focused 검증과 보고서 작성
  - diff check 및 변경 범위 확인

## 검증 계획

### 단계별 검증

- Stage 1
  - 불필요한 추상화 제외 확인
- Stage 2
  - 시각 클래스 동등성 확인
- Stage 3
  - diff check 및 변경 범위 확인

### 통합 검증

- `npm run typecheck`
- `npm run lint`
- 관련 UI smoke 또는 focused renderer 테스트
- `git diff --check`
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **wrapper 남발**: 반복도가 낮은 일회성 스타일은 유지한다.
- **semantic 손실**: `p`, `span`, `output`, `dt` 등 기존 의미를 교체 과정에서 잃지 않는다.

## 승인 요청 사항

- Issue #16을 `local/task16`에서 시작하고 위 범위와 단계 경계로 구현계획서 작성 및 후속 구현을 진행한다.
- 수행계획서 승인 전에는 구현계획서 작성, 제품 코드 변경, 검증 목적 외 변경을 진행하지 않는다.
- 범위 제외 항목은 별도 이슈 또는 별도 승인 없이는 다루지 않는다.

승인되면 `task_m012_16_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
