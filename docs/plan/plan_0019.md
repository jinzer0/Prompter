당신은 Prompter라는 Electron 데스크톱 앱을 개발하고 있습니다.

Prompter는 로컬 우선(local-first) 프롬프트 컴파일러이자 프롬프트 라이브러리입니다. 이 앱의 목적은 모호한 인간의 요청을 에이전트가 실행 가능한 프롬프트로 변환하고, 이를 버전 관리되는 프롬프트 자산으로 저장하며, Codex, Claude Code, Cursor 및 일반 LLM 에이전트에 사용할 수 있도록 내보내는 것입니다.

* id: string
* severity: "low" | "medium" | "high" | "critical"
* category: string
* label: string
* description: string
* location:

  * entityType: string
  * entityId?: string
  * field: string

* endOffset?: number
* confidence: "low" | "medium" | "high"
* recommendation: string

SensitiveScanResult:

* scannedAt: number

* findingCount: number
* criticalCount: number
* highCount: number
* mediumCount: number
* lowCount: number

safeToProceed:

* critical finding이 있으면 false 권장
* high finding만 있어도 false 또는 requires confirmation
* medium/low는 warning

이번 단계에서 구현할 주요 기능:

1. Local Sensitive Pattern Scanner

shared utility로 로컬 민감정보 스캐너를 구현합니다.

권장 위치:

* src/shared/privacy/privacyTypes.ts
* src/shared/privacy/privacySchemas.ts
* src/shared/privacy/sensitivePatterns.ts
* src/shared/privacy/scanSensitiveText.ts
* src/shared/privacy/maskSensitiveEvidence.ts
* src/shared/privacy/scanSensitivePayload.ts

요구사항:

* 순수 함수로 작성
* 네트워크 호출 없음
* LLM 호출 없음
* 입력 문자열을 변경하지 않음
* 감지된 evidence는 마스킹
* 감지 결과는 Zod schema로 검증 가능
* 성능상 너무 비싼 regex는 피함
* catastrophic backtracking 방지
* 매우 긴 텍스트도 앱을 멈추지 않게 처리
* text length limit 또는 chunk scan을 고려

2. Draft Privacy Scan

PromptCompilerPanel의 현재 draft를 스캔할 수 있어야 합니다.

대상:

* originalInput
* compiledPrompt
* manual projectContext
* techStack
* constraints
* acceptanceCriteria
* validationCommands
* additionalNotes

동작:

* 사용자가 “민감정보 검사” 버튼을 눌렀을 때 실행
* 자동 실행하지 않음
* 결과는 패널로 표시
* finding이 있어도 draft를 자동 수정하지 않음
* 사용자가 직접 텍스트를 수정해야 함
* “마스킹된 evidence”만 표시

선택:

* compiledPrompt 생성 전 originalInput에 critical secret 후보가 있으면 warning banner 표시 가능
* 단, 자동 스캔을 매 타이핑마다 실행하지 마세요.
* 비용 없는 local scan이라도 과한 자동검사는 UX를 해칠 수 있습니다.

3. LLM 호출 전 Privacy Warning

LLM analyze / compile / review 요청 전에 payload를 local scanner로 검사합니다.

대상:

* originalInput
* compiledPrompt, review 시
* manual project context
* included project context profile text
* selected harness template body
* prompt template body, 적용된 경우
* clarification answers

동작:

* 사용자가 LLM analyze / compile / review 버튼을 누름
* main process 또는 renderer에서 전송 전 local scan 수행
* critical/high finding이 있으면 confirmation dialog 표시
* 사용자가 “계속 진행”을 명시적으로 눌러야 LLM 호출 진행
* 취소하면 LLM 호출 없음
* confirmation 결과는 저장하지 않아도 됨

중요:

* OpenAI API Key 자체는 scan 대상 payload에 포함되면 안 됩니다.
* API Key가 scan finding에 등장한다면 데이터 흐름에 문제가 있을 수 있으므로 critical warning을 띄우세요.
* LLM 호출 전 scan은 local-only이며 LLM을 호출하지 않습니다.
* scan 결과를 로그로 남기지 마세요.

4. Export 전 Privacy Warning

Phase 8 export content를 생성한 후, copy 또는 file save 전에 privacy scan을 수행합니다.

동작:

* export content 생성
* local scanner 실행
* finding이 있으면 export warning dialog 표시
* 사용자가 계속 진행하면 copy/save 수행
* 취소하면 export 중단
* export content는 자동 redaction하지 않음

UI:

* finding count
* severity summary
* category별 요약
* masked evidence
* “그래도 복사”
* “그래도 파일로 저장”
* “취소하고 수정”

주의:

* Markdown export, Codex export, Claude export, Cursor export, AGENTS.md, SKILL.md 모두 적용
* export content에 secret store 값이 포함되면 안 됩니다.

5. Backup 전 Privacy Warning

Phase 16 backup export 전에 backup envelope data를 privacy scan합니다.

동작:

* backup data 생성
* secret 제외 여부 확인
* privacy scan 수행
* finding이 있으면 warning
* 백업은 평문 JSON임을 다시 안내
* 사용자가 계속 진행하면 저장
* encrypted backup을 선택한 경우에도 암호화 전 scan warning은 표시 가능
* 사용자가 취소하면 저장하지 않음

주의:

* API Key와 safeStorage 값은 애초에 backup data에 포함되지 않아야 합니다.
* scanner가 backup 내부에서 secret 후보를 찾는 경우, 이는 사용자가 prompt/context/template 본문에 직접 넣은 값일 수 있습니다.
* 자동 redaction하지 않습니다.

6. Library Privacy Scan

전체 라이브러리를 read-only로 스캔할 수 있는 Privacy Center를 추가합니다.

스캔 대상:

* prompts
* project context profiles
* prompt templates
* harness templates
* quality review improvedPromptDraft, 저장되어 있다면
* non-secret settings는 기본 제외

UI:

* Settings > Privacy 또는 Tools > Privacy Center
* “라이브러리 민감정보 검사” 버튼
* finding summary
* severity별 findings
* entity별 findings
* 관련 항목으로 이동 버튼

동작:

* scan은 read-only
* scan 결과는 자동 저장하지 않음
* 사용자가 명시적으로 “리포트 저장”을 누르면 저장 가능, 선택
* finding 클릭 시 해당 PromptVersion / context / template detail로 이동
* 자동 수정 없음
* 자동 삭제 없음

7. Privacy Center

Privacy 관련 상태와 도구를 한 곳에서 볼 수 있게 합니다.

포함:

* 민감정보 검사
* LLM 호출 전 경고 설정, non-secret setting
* export 전 경고 설정, non-secret setting
* backup 전 경고 설정, non-secret setting
* encrypted backup 안내
* 백업은 기본적으로 평문 JSON이라는 안내
* API Key는 secret store에 저장되며 백업에 포함되지 않는다는 안내

8. Encrypted Backup Export

Phase 16 backup에 선택적 암호화 기능을 추가합니다.

요구사항:

* 사용자가 “암호화된 백업으로 저장”을 선택할 수 있어야 합니다.
* passphrase 입력
* passphrase confirmation
* passphrase는 저장하지 않음
* passphrase는 renderer state에 오래 보관하지 않음
* passphrase는 로그에 남기지 않음
* 백업 data를 JSON으로 생성한 뒤 main process에서 암호화
* 파일 확장자:

  * .prompter-backup.enc
  * 또는 .prompter-backup.encrypted.json
* encrypted envelope에 schemaVersion, encryption metadata 포함

암호화 방식:

* Node.js crypto 사용
* AES-256-GCM 권장
* PBKDF2 또는 scrypt로 key derivation
* salt 랜덤 생성
* iv 랜덤 생성
* authTag 저장
* plaintext backup data는 파일에 쓰지 않음
* 가능하면 main process에서만 암호화 수행

EncryptedBackupEnvelope 구조:

* schemaVersion: number
* appName: "Prompter"
* encrypted: true
* encryption:

  * algorithm: "aes-256-gcm"
  * kdf: "scrypt" 또는 "pbkdf2"
  * salt: string, base64
  * iv: string, base64
  * authTag: string, base64
  * iterations?: number, pbkdf2 사용 시
* ciphertext: string, base64
* exportedAt: number
* metadata:

  * backupType
  * encryptedItemCounts, optional
  * excludesSecrets: true

주의:

* passphrase를 OS keychain에 저장하지 마세요.
* password recovery 없음
* UI에 “비밀번호를 잊으면 복구할 수 없습니다” 안내 표시
* API Key는 암호화 백업에도 포함하지 않습니다.
