당신은 Prompter라는 Electron 데스크톱 앱을 개발하고 있습니다.

Prompter는 로컬 우선(local-first) 프롬프트 컴파일러이자 프롬프트 라이브러리입니다. 이 앱의 목적은 모호한 인간의 요청을 에이전트가 실행 가능한 프롬프트로 변환하고, 이를 버전 관리되는 프롬프트 자산으로 저장하며, Codex, Claude Code, Cursor 및 일반 LLM 에이전트에 사용할 수 있도록 내보내는 것입니다.

현재까지 완료되었다고 가정하는 단계:

* Electron, React, TypeScript, Vite 기반 앱 골격
* main, preload, renderer 분리
* 안전한 Electron 기본 설정
* typed preload bridge
* IPC ping/pong 테스트

Phase 1:

* Tailwind CSS 기반 기본 UI
* 3단 레이아웃
* 재사용 가능한 기본 UI 컴포넌트

* DB는 Electron main process에서만 접근

* Zod 기반 IPC 입력값 검증

이 작업은 Phase 18: 로컬 인사이트 / 라이브러리 분석 대시보드입니다.

목표:
Prompter 라이브러리에 축적된 로컬 메타데이터를 기반으로 사용자가 자신의 프롬프트 라이브러리 상태를 이해할 수 있는 인사이트 대시보드를 구현합니다. 이 대시보드는 실행 결과나 외부 에이전트 로그가 아니라, 프로젝트, 프롬프트, 버전, 태그, 품질 점수, 템플릿, 하네스, 컨텍스트 프로파일, 백업/정리 상태 같은 로컬 데이터만 분석합니다.

이 단계의 핵심:

* 로컬 데이터 기반 통계
* 프로젝트별 라이브러리 상태
* 시나리오 / 대상 에이전트 분포
* 품질 점수 분포
* 미평가 프롬프트 찾기
* 오래된 프롬프트 찾기
* 버전이 많은 프롬프트 찾기
* 태그 사용 현황
* 템플릿 사용 현황, 가능한 경우
* 유지보수 이슈 요약
* prompt execution data는 계속 없음

중요:
프롬프트 실행 기능을 추가하지 마세요.
Codex CLI를 호출하지 마세요.
Claude Code CLI를 호출하지 마세요.
Cursor를 자동 실행하지 마세요.
외부 앱을 자동 제어하지 마세요.
외부 repo를 자동 스캔하지 마세요.
repo_path 기반 파일 읽기를 하지 마세요.
git 명령을 실행하지 마세요.
프롬프트 실행 결과 저장 기능을 추가하지 마세요.
prompt_runs, agent_runs, execution_results, validation_results, run_logs를 만들거나 사용하지 마세요.
OS 전역 단축키를 추가하지 마세요.
window.prompter.appEvents.*를 추가하지 마세요.
window.prompter.shortcuts.*를 추가하지 마세요.
quick_capture_* settings key를 추가하지 마세요.
이번 단계는 로컬 메타데이터 분석과 대시보드 UI에만 집중합니다.

Phase 11부터 Phase 17까지의 guardrail:

* quick capture 동작을 변경하지 마세요.
* 클립보드 텍스트를 자동 정리하지 마세요.
* 하네스 템플릿 선택 로직을 변경하지 마세요.
* 프로젝트 컨텍스트 프로파일 선택 로직을 변경하지 마세요.
* 품질 리뷰어를 자동 실행하지 마세요.
* Prompt Template 선택/적용 규칙을 변경하지 마세요.
* 백업/import 전략을 overwrite 방식으로 바꾸지 마세요.
* maintenance scan/action 정책을 자동 destructive 방식으로 바꾸지 마세요.
* 인사이트 대시보드는 자동 LLM 호출을 실행하면 안 됩니다.
* 인사이트 대시보드는 자동 정리, 자동 병합, 자동 삭제를 실행하면 안 됩니다.
* 인사이트 대시보드는 current draft를 자동 변경하면 안 됩니다.
* 인사이트 대시보드는 자동 analyze / compile / review / export / execution을 실행하지 않습니다.

분석 범위:

사용할 수 있는 데이터:

* projects
* prompt_assets
* prompt_versions
* tags
* prompt_tags
* harness_templates
* project_context_profiles
* prompt_quality_reviews, 구현된 경우
* prompt_templates
* prompt_asset_lineage, 구현된 경우
* non-secret settings 일부, 필요 시

사용하면 안 되는 데이터:

* API Key
* secret store
* safeStorage ciphertext
* clipboard content
* logs
* external repo files
* repo_path가 가리키는 파일
* prompt_runs
* agent_runs
* execution_results
* validation_results
* run_logs

주의:

* 이 대시보드는 사용자의 로컬 DB만 읽습니다.
* 네트워크 요청을 하지 않습니다.
* LLM 호출을 하지 않습니다.
* 파일 시스템을 스캔하지 않습니다.
* repo_path는 단순 문자열 metadata로만 취급합니다.

이번 단계에서 구현할 주요 기능:

1. Insights Dashboard 진입점

Settings 또는 별도 화면에 Insights Dashboard를 추가합니다.

권장 위치:

* 왼쪽 사이드바에 “Insights” 또는 “라이브러리 분석” 항목
* Tools 메뉴에 “Library Insights”
* Settings 안의 “Insights” 섹션

메뉴 추가 시:

* 기존 menu.onAction / MENU_ACTION_CHANNEL 패턴 재사용
* window.prompter.appEvents.* 추가 금지
* window.prompter.shortcuts.* 추가 금지
* globalShortcut 추가 금지

대시보드는 read-only 화면입니다.
사용자가 버튼을 눌러 특정 프롬프트나 프로젝트로 이동하는 것은 허용됩니다.
하지만 대시보드가 직접 삭제, 병합, 실행, LLM 호출을 수행하면 안 됩니다.

2. Summary Cards

대시보드 상단에 전체 요약 카드를 표시합니다.

카드 예:

* 전체 프로젝트 수
* 전체 PromptAsset 수
* 전체 PromptVersion 수
* 전체 태그 수
* 전체 Prompt Template 수
* 전체 Harness Template 수
* 전체 Project Context Profile 수
* 평균 quality_score
* 미평가 current prompt 수
* maintenance issue 수, 최근 scan 결과가 있는 경우
* 가장 최근 수정일

주의:

* maintenance issue 수는 Phase 17의 저장된 report가 없으면 즉시 scan하지 마세요.
* read-only summary query로 계산 가능한 값만 계산합니다.
* maintenance scan을 자동 실행하지 않습니다.

3. Project Health Overview

프로젝트별 상태를 보여줍니다.

표시 항목:

* project name
* promptAsset count
* promptVersion count
* average quality score
* unevaluated prompt count
* tag count
* context profile count
* last updated
* version-heavy prompts count
* empty prompt count, 쉽게 계산 가능하면

정렬:

* last updated desc
* prompt count desc
* average quality asc
* unevaluated count desc

액션:

* 프로젝트 열기
* 해당 프로젝트 프롬프트 목록으로 이동
* 해당 프로젝트 context profile 보기

금지:

* 자동 maintenance action 실행
* 자동 quality review 실행

4. Scenario Distribution

시나리오별 분포를 보여줍니다.

시나리오:

* feature
* bugfix
* refactor
* code_review
* docs
* research

표시:

* count
* percentage
* average quality score
* unevaluated count
* 최근 생성/수정된 prompt count, 선택

UI:

* 간단한 bar chart 또는 table
* 별도 chart library를 추가하지 않아도 됩니다.
* Tailwind 기반 progress bar로 충분합니다.
* chart library 추가가 부담 없으면 lightweight library를 사용할 수 있지만, 과한 시각화는 피하세요.

5. Target Agent Distribution

대상 에이전트별 분포를 보여줍니다.

대상:

* codex
* claude_code
* cursor
* generic_agent

표시:

* count
* percentage
* average quality score
* most common scenario
* unevaluated count

목적:

* 사용자가 어떤 에이전트용 프롬프트를 많이 만드는지 확인

6. Quality Score Insights

Prompt Quality Reviewer 결과를 기반으로 품질 인사이트를 보여줍니다.

표시:

* average quality score
* score distribution

  * 90-100 excellent
  * 75-89 good
  * 60-74 usable
  * 40-59 needs work
  * 0-39 weak
  * no score
* lowest quality current prompts
* highest quality prompts
* unevaluated current prompts
* scenario별 평균 점수
* targetAgent별 평균 점수

액션:

* low quality prompt 열기
* unevaluated prompt 열기
* quality review panel로 이동

금지:

* 자동 quality review 실행
* 자동 improvedPromptDraft 생성
* 자동 score 업데이트

7. Version Activity Insights

PromptVersion 데이터를 기반으로 버전 활동을 보여줍니다.

표시:

* 버전이 가장 많은 PromptAsset
* 최근 7일 / 30일 / 전체 version 생성 수
* 평균 versions per prompt
* current version이 오래된 prompt
* created_at / updated_at 기준 활동 추이

주의:

* 날짜 범위 필터는 local DB timestamp 기반
* 자동 알림이나 scheduled task 없음
* background analytics 없음

8. Tag Insights

태그 사용 현황을 보여줍니다.

표시:

* 가장 많이 사용된 태그
* 사용되지 않는 태그 수
* 프로젝트별 태그 분포
* scenario별 자주 쓰이는 태그
* 품질 점수가 낮은 prompt에 많이 붙은 태그, 선택
* 중복 태그 후보 수, Phase 17 유틸 재사용 가능

액션:

* 태그 필터로 이동
* maintenance duplicate tag panel로 이동, 가능하면
* unused tags maintenance로 이동

금지:

* 자동 tag merge
* 자동 unused tag delete

9. Template Insights

Prompt Template과 Harness Template 현황을 보여줍니다.

Prompt Templates:

* 전체 수
* scenario별 수
* targetAgent별 수
* source prompt가 있는 template 수
* source가 missing인 template 수, 계산 가능하면
* placeholder variable이 많은 template
* 최근 수정된 template

Harness Templates:

* 전체 수
* scenario별 수
* targetAgent별 수
* builtin/user template 구분, 구현된 경우
* invalid required_fields / clarification_policy 후보 수, 계산 가능하면

액션:

* template 관리 화면으로 이동
* harness 관리 화면으로 이동

금지:

* 자동 template 수정
* 자동 template cleanup

Project Context Profile 현황을 보여줍니다.

표시:

* 프로젝트별 context profile count

* tech_stack이 비어 있는 profile 수

액션:

11. Maintenance Snapshot

* high / medium / low issue count
* “Maintenance 열기” 버튼

없으면:

* “최근 유지보수 스캔이 없습니다.”
* “Maintenance 화면에서 수동 스캔할 수 있습니다.”

주의:

* Insights Dashboard가 자동으로 maintenance scan을 실행하면 안 됩니다.
* scan은 사용자가 Maintenance 화면에서 명시적으로 실행해야 합니다.
